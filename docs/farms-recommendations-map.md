# تقارير المزارع والخريطة والتوصيات — حالة التنفيذ

## التوصيات
`POST /api/farms/{farm_id}/advice` ينشئ سجل إرشاد أولياً مرتبطاً بمحصول موجود في قطعة من المزرعة. الإصدار الحالي يجمع المدخلات الناقصة ويعرض فجوات الأدلة ودرجة ثقة صفرية بدلاً من اختلاق جرعات أو توصية زراعية محلية. بيانات قاعدة المعرفة السورية لم تُراجع محلياً بعد.

## تقارير الاحتياجات
- `GET /api/farms/{farm_id}/report`: تقرير JSON بالمزرعة والقطع والمساحة والسجل المتاح.
- `GET /api/farms/{farm_id}/report.csv`: تنزيل قائمة القطع بصيغة CSV متوافقة مع العربية.

هذه تقارير إدارية لما أدخله المستخدم، وليست قياسات لحالة الحقل أو تقييم إنتاج.

## قاعدة البيانات الفعلية
عند ضبط اتصال PostgreSQL، تُحفظ المزارع والحقول والتوصيات في الجداول `farms`, `fields`, و`recommendations`. جدول `fields` يخزن نقطة مكانية PostGIS عند إدخال إحداثيين. التشغيل دون قاعدة بيانات يستخدم ملفات JSON محلية، ولا ينشئ سجلات مزارع تجريبية.

طبق مخطط القاعدة على قاعدة جديدة أو استخدم أداة migrations للموجودة؛ لا تحذف مجلد volume أو ملفات البيانات. `data/sql/postgres_init.sql` يُنفذ تلقائياً فقط عند إنشاء volume جديد في Docker.

## خريطة المناطق السورية
الخريطة تعرض مواقع القطع عند إدخال الإحداثيات. تُرجع `GET /api/regions/map` حدوداً إدارية فقط إذا أُضيفت هندسة GeoJSON موثقة ومصدرها إلى قاعدة المعرفة. حالياً لا توجد حدود رسمية مستوردة، ولذلك لا يرسم النظام مضلعات تخمينية. طبقة بلاطات OpenStreetMap تحتاج اتصالاً بالإنترنت وسياسة الاستخدام المناسبة؛ يمكن لاحقاً إعداد tiles محلية للعمل دون اتصال.
